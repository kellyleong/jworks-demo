# 駿旺工務管理系統｜JWorks

[開啟 GitHub Pages 試用版](https://kellyleong.github.io/jworks-demo/)

「駿旺工務」（JWorks）是為駿旺建築工程有限公司專門訂製的保養管理示範程式，正式全名為「駿旺工務管理系統」。JW 代表駿旺，Works 代表工務。介面及手機名稱使用「駿旺工務」。產品只服務這間公司，不提供其他公司的開通或公司切換，提供管理端、工人端和顧客端。

物業分為住宅、寫字樓、商鋪；服務分為日常保養、E Call、加改工程。每張服務工單是一項具體工作的記錄，由公司按照保養計劃或電話、通訊軟件、電郵收到的需求建立；一個物業可有不同類型的服務工單。

## 已實作的流程

- 管理端：保養總覽、保養地點、服務工單、派工排程、工人、工時、相片及顧客。公司名稱為駿旺建築工程有限公司，沒有公司設定頁。
- 派工提示：新增工單或調整派工時，優先突出有空的工人，並列出衝突工人的重疊工單及時段。按同日所有物業的派工計算，排除目前編輯的工單、已完成及待驗收工單；首尾相接不算衝突。提示不阻止儲存，仍由管理人員決定安排。
- 顧客聯絡：可新增顧客，並獨立輸入、編輯各自的姓名、公司／單位、電話及電郵；顧客亦可在自己的工作台編輯聯絡資料。
- 技工技能：一位工人可有多個技能標籤，支援編輯、自訂及技能篩選；管理端頂欄可搜尋工人姓名、工種、電話或技能，並開啟該工人的派工排程。公司派工時顯示技能，顧客端只顯示工人姓名及到訪安排。
- 保養跟進：公司登記日常保養、E Call 或加改工程，再確認工人及到訪時間；改期亦由公司處理。顧客查閱已登記、已安排及已完成的服務，沒有發起工單、到訪確認、改期或完工驗收的操作入口。
- 工單處理紀錄：派工、安排確認、到場、暫離、返回、結束打卡、工作回報及公司完工確認記錄於工單。完工文件由工人結束打卡並提交回報時產生，與工單關聯；公司可由工單詳情或完工文件確認同一份記錄。手動建立服務文件只提供報價。
- 後續工作：需補充處理或再次到訪時，公司在本次工作確認流程建立關聯的後續工單，與原工單確認一併儲存。原工單保持完成，出勤、相片及回報保留。
- 工人端：查看派工、定位打卡、現場相片、材料及結構化處理回報。回報依設備、位置、現場情況、處理項目、結果及後續安排填表，補充文字可選填，減少依賴自由描述。
- 出勤覆核：保留定位精度、距地點距離、定位取得時間及時間來源；所有已結束出勤均由辦公室覆核及核准計薪工時。定位不足、過期、超出範圍或例外申報保留原因。每筆已核准工時可獨立修改或重置為待覆核，計薪工時可高於打卡記錄。
- 顧客端：各物業的保養總覽、目前跟進、下次到訪、過往完成記錄、相片及文件查閱。工人提交回報並結束打卡後，首頁、物業詳情、搜尋及服務記錄均顯示已完成；公司完工確認與顧客狀態分開。報價以已簽合約或確認電郵辦理，由公司登記確認依據。報修及其他溝通沿用電話、通訊軟件或電郵。
- 營運報表：按日期統計服務工作量、完成率、逾期及後續工作、派工人力、工時核准構成、E Call 派工回應、處理時間及公司完工確認待辦。支援 CSV 匯出。

程式不設工程預算、成本或財務報表。報價金額僅供查閱，正式確認經合約或電郵辦理。

## 資料與通知

現有完整網站的業務記錄儲存於 D1，相片儲存於 R2。GitHub Pages 試用版則把記錄及相片存於每人的瀏覽器 IndexedDB；各裝置的試用資料獨立，不會互相同步。兩種部署皆可重新載入頁面後繼續操作，程式內通知和工單狀態每 30 秒更新，提交操作後立即更新目前工作台。

靜態版每次操作在同一 IndexedDB 讀寫交易內讀取及更新資料；相片先讀取檔案，再於交易內加入現有記錄，避免同一瀏覽器多個分頁互相覆寫。伺服器版在寫入出勤時核對工單當前狀態及派工資格；派工資料與處理歷史在同一更新中儲存，已開始或已回報完成的工單不能被並行派工操作改回待出發。

保養回應時間由收到工單至首次派工計算；處理時間由首次到場至首次完工回報計算。沒有完整事件的工單不加入平均值。工時只包括已離場結算的記錄。

所有初始物業、工作、人物及文件均為示範資料。示範日期為 2026-10-08。新增操作保留實際記錄時間；新上載相片按澳門時區記錄上載日期，伺服器版使用伺服器時間，靜態版使用裝置時間。既有資料升級時保留工單、顧客及相片關聯。

開啟 demo 即有服務工單、歷史回報及工時，營運報表直接顯示這些資料，不設載入示例或示例專用篩選。初始工人由 16 位精簡為 8 位，保留冷氣、電力、泥水、木工、油漆、消防及水喉工種；歷史出勤精簡為 5 筆，保留暫離、核准、核減及待覆核案例。GitHub Pages 升級時自動補入缺少的歷史工單及相關記錄，既有工人、已操作資料及相片不重設。

伺服器版打卡由伺服器收到提交時記錄時間，不能在工人表單自行填寫。定位比對新取得的座標、精度及保養地點範圍；GPS 符合只能表示定位資料符合條件，不能單獨證明工人身分或排除虛擬定位。GitHub Pages 使用裝置時間，其打卡一律標示待覆核。正式登入及裝置身分核實尚未接入，現階段不能聲稱為完整防偽出勤系統。
