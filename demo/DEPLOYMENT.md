# 駿旺工務｜JWorks：GitHub Pages 試用版

這個版本沿用管理端、工人端及顧客端的同一套介面。物業分為住宅、寫字樓、商鋪，服務工單分為日常保養、E Call、加改工程；包括可用工人及衝突提示、技工技能與搜尋、結構化處理回報、定位及出勤覆核、相片、工時、報價查閱及正式確認登記、公司完工確認、後續工單、營運報表和手機版面。

工單由公司根據計劃或電話、通訊軟件、電郵需求建立，安排及改期亦由公司處理。顧客端查閱保養總覽、到訪安排、過往服務及文件，沒有發起工單、到訪確認、改期、完工驗收或報價確認的操作入口。工人提交回報並結束打卡後，顧客首頁、物業詳情、搜尋及服務記錄統一顯示已完成。

完工文件由工單回報流程產生，公司由工單詳情或文件確認同一份工作記錄；手動建立文件只提供報價。需要再次到訪時，在本次工作確認流程另建關聯的後續工單，保留原工單的完成狀態、出勤、相片及回報。

試用資料及相片儲存在使用者瀏覽器的 IndexedDB。重新整理頁面後仍可繼續操作；同一個瀏覽器切換角色可體驗完整跟進流程。不同裝置或不同使用者的試用資料不會互相同步。清除此網站的瀏覽器資料後會回到初始示範資料。既有瀏覽器資料升級時保留工單、顧客及相片關聯。這個版本沒有正式登入、共用資料庫或背景手機推播。

demo 本身已包含完整示範資料，無需另外載入示例。初次開啟即有 8 位工人、待辦工單，以及 5 張歷史工單與 5 筆已結束出勤；報表直接統計現有資料，只保留日期及物業類別篩選。歷史資料涵蓋暫離、核准、核減及待覆核，沒有活動中的示範打卡。舊瀏覽器資料會自動補入尚未存在的歷史工單及關聯記錄，不覆寫既有工單、工人、出勤或相片；已儲存的工人名單維持原狀。

選擇工人「梁永成 · 冷氣技工」可查看示範當日（2026-10-08）0 項工作及「今日尚未派工」，歷史維修與工時仍保留。舊版未經操作的空調保養派工會自動移除梁永成；已有出勤、相片或後續操作的工單維持原安排。

選擇「張國明 · 油漆技工」可查看同日「今日工作已全部完成」及展開的完成清單。牆身修補已有回報、已結束打卡、3 小時已核准工時及公司確認的完工文件；除 5 筆歷史出勤外，另有這 1 筆當日出勤。升級只同步尚未操作的預設工單，已有出勤、相片、完工文件或後續操作者保留原記錄。

每次操作在同一讀寫交易內讀取及更新記錄，避免同一網站的多個分頁互相覆寫資料。相片先讀取檔案，再加入交易當下的記錄；新相片以裝置時間按澳門時區記錄實際上載日期。初始示範日期仍為 2026-10-08。

靜態版打卡使用裝置時間，即使定位符合亦列為待覆核，不是可信伺服器時間的出勤證明。定位保留精度、取得時間及距物業距離；定位不足或例外申報由辦公室覆核。GPS 資料不能單獨證明工人身分或排除虛擬定位。伺服器版才使用收到提交時的伺服器時間；目前正式登入及裝置身分核實仍未接入。

## 編譯

在完整來源專案使用 Node.js 22.13 或以上建置；GitHub 發佈儲存庫只保存建置結果及說明文件：

```sh
npm ci
npm run build:pages
```

輸出目錄為 `docs/`。相片不會上載至 GitHub，也不會加入儲存庫。

## GitHub Pages

1. 建立 `jworks-demo` 儲存庫，或選擇要使用的既有儲存庫。
2. 提交更新後的說明文件及編譯後的 `docs/`，移除被新建置取代的舊資源，並保留 `docs/.nojekyll`。原始工作區把輸出目錄列入忽略項目，從來源工作區手動提交時使用 `git add -f docs`。
3. 在 Settings → Pages 選擇 Deploy from a branch，分支 `main`，目錄 `/docs`。
4. GitHub Pages 發佈成功後，使用該頁顯示的 `github.io` 網址開啟程式。

建置資源使用相對路徑，可在儲存庫網址的子目錄正常載入。正式全名「駿旺工務管理系統」只在管理端顯示；其他介面及手機名稱為「駿旺工務 / JWorks」。
